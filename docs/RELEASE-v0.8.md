# v0.8.0 — local knowledge operations and Language Wind

AI host now uses native knowledge operations and grounded memory expression. Normal host/neural chat never selects a generative model call. The explicit `foundation_once` comparison API remains available for controlled benchmarks and its failure/partial-output tests.

Added:

- Versioned native Language Wind grammar, typed entities, demonstrated operations, learned preconditions/effects, prediction, simulation and explicit uncertainty/conflict.
- Local eligibility updates and bounded recurrent predicate activation with inspectable trajectories. These are software mechanisms, not biological validation.
- Transfer across unseen entity/property combinations; later demonstrations can add a newly discovered prerequisite. Simulation never becomes its own training evidence.
- Model-bound Qwen representation readout training, 30-example split curriculum, native SGD, held-out reporting, unchanged checksummed Wind ABI and separate explicit activation.
- Authoritative Arc persistence, RNA-prepared astroengram traces, immutable worker snapshots, version-checked coordinator writes and stable-pulse crash deduplication.
- Background archive/web review for missing general knowledge, scoped evidence arrival and attributed later contributions. Runtime network acquisition is enabled by default with an explicit offline option.
- React Activity knowledge inspector, language training/activation controls, correct host description and visible v0.8.0 version.

The existing pack adapter still uses the user's b9870 llama/GGML/CUDA DLLs without a CUDA rebuild. No Boost, TypeScript or ML framework was added. All policy.wind files retain the 1152-byte ABI and existing maturity/weight bounds. Training and passing tests never activate candidates.

Read [QUICKSTART-v0.8.md](QUICKSTART-v0.8.md) for startup, chat instructions, learning examples, optional Qwen training and offline operation. [COGNITIVE-RUNTIME.md](COGNITIVE-RUNTIME.md) defines the actual algorithms and limitations. [VALIDATION-v0.8.md](VALIDATION-v0.8.md) records tested platforms and remaining gaps.

The release archive includes a complete `RELEASE_MANIFEST.json` with per-file hashes and changes from v0.7.3. It contains no personal model, DLL pack, configuration or logs.
